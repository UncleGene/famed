# When to use
- Use when a validated derived insight needs to be recorded in the append-only findings ledger.
- Use when a finding must be superseded after an evidence-rule update.
- Use when findings citing a corrected source/report must be marked stale.
- Do not use to generate new medical conclusions. This skill maintains the ledger after a finding has already been reviewed or generated by an appropriate workflow.

# Inputs
- `person_id` when recording or person-scoping stale markers.
- Finding statement, health domain, evidence tier (`E1`-`E5`), confidence (`0`-`1`), and source paths.
- Optional finding ID when caller needs deterministic IDs.
- Existing finding IDs for supersession.

# Procedure
1. Verify each finding has at least one source path. Do not record uncited findings.
2. Verify `E1`/`E2` findings have a completed evidence check; otherwise record as a lower tier or stop for review.
3. Invoke the internal helper from the repo root:

   ```bash
   python scripts/findings_ledger.py record \
     --person-id <person_id> \
     --domain "Medication Safety" \
     --statement "<finding>" \
     --evidence-tier E3 \
     --confidence 0.70 \
     --source-path Records/<person_id>/Reports/genetics.md
   ```

4. For supersession, append a supersession event instead of editing the old row:

   ```bash
   python scripts/findings_ledger.py supersede \
     --finding-id <old_id> \
     --superseded-by <new_id> \
     --reason "<why>"
   ```

5. For source corrections, mark active findings citing that source stale:

   ```bash
   python scripts/findings_ledger.py stale-source \
     --person-id <person_id> \
     --source-path Records/<person_id>/Reports/current-medications.md \
     --reason "<why>"
   ```

# Skeptic pass
- Stop if a finding lacks source paths.
- Stop if an `E1`/`E2` finding is not evidence-check verified.
- Do not edit or delete `ledger/findings.jsonl`; all changes append a new JSONL event.
- Treat `stale` and `superseded` findings as unavailable for current reports until regenerated.

# Output

```md
- Ledger path:
- Event:
- Finding ID:

- Source paths:
```

# Hand-off
- Need a new AI-derived insight -> future evidence validation / multi-agent insight workflow.
- Need a doctor-facing visit summary -> `fm-prepare-doctor-visit`.
- Need conservative medication-safety review alerts -> `fm-generate-medication-safety-alerts`.
- Need deterministic FHIR export for Patient, lab Observation, medication MedicationStatement, lab DiagnosticReport, accepted-history Condition, family-graph FamilyMemberHistory, and canonical Immunization resources -> `fm-export-fhir`.
- Need expanded FHIR resources, disease probability scoring, interaction severity scoring, or interpreted PGx output -> future report/export workflow.
